Connect your archive station

NightCopy runs on Netlify at nightcopy.coletechsystems.com. Local file import, folder copy, duplication, downloads and ZIP packaging work in the browser. Cloud providers require your own sign-in and the setup below.

1 / Private Supabase vault

  1. Open the ColeTech Supabase SQL editor as the project owner.
  2. Download the NightCopy SQL setup, paste it into the SQL editor and run it. It creates one private nightcopy bucket and a transfer receipt table. Existing ColeTech tables are unchanged. Each signed-in user can only read and create objects under their own user ID.
  3. In NightCopy → Connections, sign in with an existing Supabase email/password account. Select Supabase vault in either pane. Successful listing changes the badge to PRIVATE / READY.

Connection defaults point to the ColeTech/Nexus project. Only its public publishable key ships in the app. Each account gets its own private file namespace; file transfers never use a service-role key.

2 / Google Drive: your archive Google account

  1. Sign into the Google Cloud credentials console using the Google account that owns your project. Create or select a project and enable the Google Drive API.
  2. Configure the Google OAuth consent screen. For a personal testing app, add your archive Google account as a test user. NightCopy requests the Drive scope for browsing, copying and transferring your Drive files.
  3. Enter your archive email in NightCopy Connections. Create an OAuth client of type Web application. Add these authorized JavaScript origins:
https://nightcopy.coletechsystems.com
https://nightcopy-coletech.netlify.app
  1. Copy the client ID ending in .apps.googleusercontent.com into NightCopy → Connections → Google OAuth web client ID. Save settings.
  2. Click Connect Google Drive and select your archive Google account. After Google grants access, NightCopy checks the actual Drive account before enabling file operations.

This direct Google sign-in uses a popup and does not require a client secret or redirect callback. Google tokens are kept in memory for this tab. If a token expires, reconnect from the button. The account connected to Codex is independent of NightCopy’s Google authorization.

Alternatively, if you already enable the Google provider in Supabase, authorize https://yeqdoxqtevchtcbannwf.supabase.co/auth/v1/callback as its OAuth redirect and add https://nightcopy.coletechsystems.com/ to the Supabase auth redirect allowlist. NightCopy can then use the Supabase Google PKCE login flow.

Copy stores the selected items in NightCopy’s clipboard. Paste targets the active pane. Transfer targets the opposite pane. Every queued write shows its destination for review. Stop cancels pending work; files already completed remain.

Browser and file limits

Use current desktop Chrome or Edge to mount writable local folders and USB drives. Other browsers can import files/folders and download the copies. Staged files stay in this tab’s memory and are cleared when it closes. ZIP creation and cloud-to-local buffering are limited to 256 MB. Standard Supabase uploads are limited to 50 MB per file. Google uploads use a resumable upload session, with progress from actual upload bytes; interrupted sessions currently need a fresh retry. Folder transfers include empty directories. A mounted folder and its contents remain subject to your browser’s permission choices.

Google Docs and drawings export as PDF/PNG, sheets as XLSX; unsupported native Google formats report an error. Drive file duplication preserves supported native documents. Shortcuts are not followed. ZIP entries retain relative paths and include a manifest. Sources remain in place.
